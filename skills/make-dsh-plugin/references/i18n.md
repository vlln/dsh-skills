# 插件 i18n（dsh Web GUI）

给插件作者：**界面文案该住在哪、怎么切语言、宿主那一半怎么办**。

**来源**：官方 `packages/client/locale`（`LocaleRuntime`／用户偏好／语言包／`resolveText`）、
`scripts/verify-client-ui-i18n.ts`（官方门禁：译文只允许住在字典文件里）、
`docs/cookbook/adding-a-package.md` §5（包显示元数据 `locale/*.json`）、
`packages/util/package-manifest`（`LocalizedText` / `PluginLocalizedMeta`）、
`packages/settings/settings`（`ctx.settings.describe()`，Node 侧读偏好的依据）、
以及官方参考实现（`ui-commands` 的 `command` 字典、`ui-model-selection` 的注册写法、
`packages/compaction/command-compact` 的宿主英文文案）。
基线 **0.2.0-rc.2**（tag `dsh-v0.2.0-rc.2`）；官方文档更权威，冲突时以官方与**安装的运行时**为准
（复核方法见 [SKILL.md](../SKILL.md) 的「溯源」节）。

## 0. 先分流：这段文案归谁

| 文案出现在哪 | 归属 | 做法 |
|---|---|---|
| 浏览器 UI（按钮、标签、tooltip、`aria-label`、空态、计数） | **客户端字典** | §1 `ctx.locale.register(ns, { zh, en })` |
| Plugins 页里本插件的**标题/描述** | **包显示元数据** | §2 `locale/en.json` + `locale/zh.json` |
| 宿主产生的用户可见文本（命令回执、工具结果、注入消息） | **Node half** | §3（官方自己留英文；要本地化有两条路） |
| 模型可见文本（tool/schema description、prompt 片段） | **不是 UI 文案** | 不进字典——模型读的是语义，翻译它只会动 prompt 缓存 |

## 1. 客户端字典（主路径）

**注册**（两种随包语言都要给，缺一个在官方是类型错误；语言切换即时生效、不需要重挂载）：

```js
export const inject = ['locale']

export function apply(ctx) {
  ctx.effect(() => ctx.locale.register('loop', { zh, en }), 'loop: dictionaries')
  // 组件经 slot 注册项的 locale 拿 t；非 slot 面用 ctx.locale.bind('loop')
  ctx.slots.inject('conversation.input.dock', () => ctx.slots.register({
    name: 'conversation.input.dock', id: 'loop', order: 15, locale: 'loop',
  }, LoopBar))
}
```

- **键写成点分小写、至少两段**（`label.fork`、`empty.noSessions`、`token.goal`）——官方门禁
  `verify-client-ui-i18n` 正是靠这个形状把 `t('label.x')` 的实参认作**键**而不是硬编码文案；
  一段式（`'fork'`）会被当成文案。
- **译文只许住在字典文件里**：官方门禁只放行 `locale.ts` / `locales.ts` / `locales/` 目录下的字面量；
  展示代码里的 JSX 文本与 `label` / `title` / `placeholder` / `aria-*` 这类属性都会被拦。
  第三方仓库没有这道门禁，但照同一条纪律写，升级/迁移时才不会返工。
  **手写单文件 bundle 的变体**（无构建步骤、浏览器只加载一个脚本，如 `vlln/dsh-autofork`）：
  字典就地内联成模块级 `DICTS = { zh: {…}, en: {…} }`，用仓库自带门禁守"字典之外没有中文文案
  字面量"（见 §6）。
- **命名空间是自己的**（如 `'loop'`、`'settings.loop'`），不要往 `common` 里塞自己的词
  （`common` 是宿主共享词的兜底命名空间：查表先走本 ns，再走 `common`，最后显示键本身）。
- **官方控件不读 locale**：`ui-primitives` 的所有 `label` / `*Label` / `labels` 都必须由你传入
  **已本地化**的字符串（见 [ui-style.md](ui-style.md) §8）。
- **`t` 每次渲染现取**：字典后注册也能被已挂载的 UI 拿到；切换语言时组件重渲、`<html lang>` 同步更新。
- **新增语言包**（不是翻译自己的文案，而是支持一门宿主没有的语言）：
  `ctx.locale.addLanguage({ id: 'ja', label: '日本語', fallback: 'en' })`——`fallback` 必须已注册且链终止于 `en`。
- **包文本映射**：`ctx.locale.resolveText(LocalizedText)` 解析 `{ en, zh }` 形状的文本
  （插件标题/描述这类），字面量原样返回。

## 2. 包显示元数据（Plugins 页的标题与描述）

装完插件后在官方 Plugins 页/插件清单里显示的名字与一句话介绍，走**文件**而不是代码：

```json
// locale/en.json（发现入口）
{ "meta": { "title": "Autofork", "description": "Fork the session when the agent is busy." } }
// locale/zh.json（同字段，其它语言照此）
{ "meta": { "title": "自动分叉", "description": "Agent 忙时自动分叉会话。" } }
```

- `package.json` 两处要一起改，否则发布出去就丢：
  `exports` 加 `"./locale/*.json": "./locale/*.json"`，`files` 加 `"locale/*.json"`。
- **回退链**（宿主读文件、不激活插件）：标题 = locale `meta.title` → `package.json.name` → Cordis 插件名；
  描述 = locale `meta.description` → `package.json.description` → 无。
- 字段可缺；**存在就必须是非空字符串**，JSON 写坏会给该插件一条诊断（其余字段仍可用）。
- 图标同源：`package.json` 顶层 `icon`（见 [SKILL.md](../SKILL.md) Step 2b）。

## 3. 宿主侧（Node half）——官方立场与两条本地化路

**官方立场：宿主文案留英文。** 实例：`command-compact` 的 `description`
（`'Compact older conversation history'`）与它全部回执文本都是英文；菜单里那句中文本地化描述
由**客户端**字典提供（`ui-commands` 的 `command` 命名空间，`label.compact` →「压缩」）。
第三方宿主命令拿不到这份客户端行外观（原因与贴面做法见 [gotchas.md](gotchas.md) 13 与
[ui-style.md](ui-style.md) §10.7）。

如果插件**必须**让宿主文案跟随界面语言，两条路：

**A（推荐）读用户设置里的语言。** 官方把语言偏好持久化成设置命名空间 **`locale`** 的字段
**`preference`**（BCP 47，如 `zh` / `en`）：

```js
// Node half：ctx.inject(['settings'], …) 之后
const d = ctx.settings.describe().find(x => x.ns === 'locale')
const lang = d?.value?.preference ?? d?.user?.preference   // undefined = 用户没显式选过
```

- ⚠️ **必须处理 `undefined`**：用户没选过语言时，客户端按 **浏览器**语言回退，宿主无从得知
  ——此时用英文（或插件默认语言），不要猜。
- 命令描述这类**注册期**文案：语言变化后需要**重新注册**才能改（`commands/change` 通知会让面板刷新），
  或在回执文本上做（每次执行现读）。

**B 客户端回传**（`locale` 命名空间读不到时，例如更老基线或自定义条目 id）：客户端把
`ctx.locale.getSnapshot().active` 经插件自己的 HTTP 路由回传，宿主缓存并据此选词——
`vlln/dsh-loop` 的既有做法（`relayLanguage` + 状态路由上的 `?lang=`）。代价是多一份状态、多一条路由，
收益是**不依赖**宿主设置文档的形状。

## 4. 改造清单（把硬编码中文搬进字典）

1. 建 `src/client/locales/zh.js` + `en.js`（或单文件 `locale.ts` 导出 `{ zh, en }`），按 UI 区域分键
   （`bar.*` / `dialog.*` / `empty.*` / `aria.*`）。
2. `ctx.locale.register(NS, { zh, en })`，`apply` 的 `inject` 加 `'locale'`。
3. 组件：slot 注册项加 `locale: NS` 拿 `t`；非 slot 的模块级函数改成接收 `t`（**不要**把 `t` 存进模块全局）。
4. 逐条替换硬编码：**同一句重复出现时合并成一个键**（清单里已按行号合并）。
5. 特殊形态单独处理，别硬套：
   - **拼字符串**（`'（' + id + '）'`）→ 改成带占位符的完整句，或把括号做进模板：`t('bar.sessionLabel', { name })`
     （**不要**把可翻译的括号/量词留在代码里拼）。
   - **动态状态词表**（`idle: { text: '空闲' }`）→ 键化（`state.idle`），词表只留键。
   - **来自服务端/日志的文本**（会话标题、模型输出）→ **不是**你要翻的文案，保持原样。
   - **调试日志 / `data-*` / CSS 变量名 / 内部标识** → 不动。
6. 包显示元数据：按 §2 加 `locale/*.json` + `exports` + `files`。
7. Node 侧按 §3 决定（英文 / 读 `locale.preference` / 回传）。

## 5. 验证

- **两种语言各看一遍**：所有可见文案跟着变，没有漏网的硬编码（可在浏览器里 Ctrl+F 找中文片段）。
- **三种语言状态**：用户选 `zh` / 用户选 `en` / **用户没选**（浏览器语言回退）——第三种最容易漏。
- **所有文案面**：按钮、标签、tooltip、`aria-label`、空态、错误提示、计数与量词。
- **包元数据**：Plugins 页在两种语言下的标题与描述正确（含未选语言时的回退）。
- **宿主文案**（若走 §3）：改语言后**下一次**回执即切；缓存要失效。
- **别翻模型可见文本**：tool / schema description 保持英文（翻了会动 prompt 缓存且无语义收益）。
- 参考实现：`vlln/dsh-loop`（客户端字典 + 宿主回传）、官方 `ui-commands`（一等公民命令字典）、
  `ui-model-selection`（`ctx.inject(['commandUi', …])` 里 `register` 带本地化 `label()`/`description()`）。

## 6. 参考实现与门禁（`vlln/dsh-autofork` 0.15.0 实测）

一份把三条路都走通的实例（**两层字典 + 回传 + 门禁**），可直接照抄形状：

- **客户端**（`client/index.js`，手写单文件）：模块级 `var NS = 'autofork'` + `var DICTS = { zh, en }`
  + `var t = function (key, params) {…}`（**默认走内联中文**：`locale` 服务缺席时界面不会变成键名）。
  `apply` 里 `ctx.inject(['locale'], …)` → `ctx.effect(() => locale.register(NS, DICTS))` + `t = locale.bind(NS)`
  （`bind` 返回的引用**每次调用现取当前语言**，所以语言切换无需重挂载）。
- **语言回传**：客户端把 `locale.getSnapshot().active` 记进一个变量，由**既有的 1s 轮询**带上
  `&lang=`；Node half 在路由里 `setLang(lang, { relay: true })`。**回传优先于设置文档**——
  用户没显式选过语言时宿主读设置只能看到"没选"，而浏览器已按 `navigator` 定下语言。
- **宿主**（`src/locale.mjs`）：`setLang/getLang/t` + `attachSettings(ctx)`（嵌套
  `ctx.inject(['settings'], …)` 读 `locale` 命名空间的 `preference`，`describe` 抛错也吞掉）。
  工具结果、注入正文、容器转写行、会话标题兜底全部走 `t()`。
- **可观测面**：health 路由多下发一个 `lang` 字段 ⇒ 真机上一条 `curl …?lang=en` 就能验证
  "回传到了没、白名单过没过"（`fr` 应被忽略、`zh-CN` 应取 `zh`）。
- **刻意不翻译**（写在门禁注释里，免得后人当漏网之鱼）：工具/schema 的 `description` 与
  digest 类**模型可见注入正文**——官方立场就是宿主侧不本地化，翻译它们只会动 prompt 缓存与
  模型行为；以及日志与 effect 标签。

**两处门禁**（自证：先用变异夹具证明它会拒，再让它守仓库）：

1. **字典自洽**：zh/en 键集相等、键是点分小写（≥2 段）、值非空、**同一个键两侧的 `{占位符}` 集一致**
   （只在一侧写对 ⇒ 另一种语言下露出 `{count}` 原文）；
2. **字典之外无硬编码文案**：扫描展示代码里的中文/全角字面量，只放行诊断串与单字符排版符号。
   （`dsh-autofork` 的门禁 5/6 就是这么写的：客户端 73 键 + 宿主 32 键。）

### 6.1 一条踩过的坑：可翻译文本**不能**用字符偏移量跨半边传

场景：宿主在正文前拼一段"来自哪条会话"的前缀（给模型看），客户端卡片要**剥掉**它——最早的做法是
宿主下发 `prefixLength`、客户端 `text.slice(prefixLength)`。**前缀一旦进字典就坏了**：切语言后
长度变了，偏移量把正文切掉一截，**静默、只在真机上出现**。

正解：宿主下发**纯正文**（`bodyText`），偏移量只作旧消息的兼容路径；或者让渲染方自己拼前缀。
**判据**：任何"另一半按长度切"的契约，只要那段文本可翻译，就是定时炸弹。

## 未确认与已知边界

- **官方门禁只覆盖官方仓库**：`verify-client-ui-i18n` 不跑在第三方仓库上，纪律靠自觉。
- **第三方宿主命令的行外观没有官方入口**（本地化 label/description 与 icon 都拿不到）——
  见 [gotchas.md](gotchas.md) 13；已作为生态 issue 提出。
- **`locale` 命名空间的可读性依赖条目处于 ACTIVE**：`ctx.settings.describe()` 只列活跃条目；
  宿主侧读不到时按 §3-B 回退。
- 未核：`ctx.locale` 在 **Desktop（Electron）** 外壳下的语言来源差异（`__DSH_LOCALE__` 预载路径）
  ——Desktop 由原生壳提供宿主偏好，普通浏览器走 navigator 检测。
