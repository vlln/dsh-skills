# 产品边界：数据放哪、向 agent 暴露什么、用什么面

> **本文件回答**：插件替用户“做东西”时的四条边界——用户数据放哪、给 agent 看什么、
> 该给工具面还是 skill + 命令、面板与会话谁服从谁。**不回答**：`dsh` 字段与 entry 契约（→ 04）、
> 安装与验证（→ 10）、UI 视觉（→ 06）。

**来源**：`dsh-motion` 的一次返工。插件先长成“自己的安装目录就是项目”，随后用路径隐藏、系统提示、
11 个工具去补，越补越偏；用户三次指出后砍到“skill + 命令 + 面板”。下面每条都带那次的具体症状。

---

## 1. 用户数据属于用户，不属于插件的安装目录

**错误形态**：插件包里放一份 `timeline.json`（示例片），面板和工具都读写它。
于是**任何会话一打开都看到同一部示例**，而 agent 想改画面只能去插件目录里改代码——在用户工作区之外。

**规则**

- 用户产物只落在**用户工作区**（本项目里是 `<workspace>/motion/`，含时间轴、场景代码、产物）。
- 工作区没有产物时，界面给**空状态**并指向得到它的正常途径（“在对话里说你要什么”），不给示例。
- 示例只服务开发与门禁：`npm run preview` 看它，真实会话永不读它。
- 初始化 = 在用户目录里放一份**空白起步件**（一个空白场景），不是把示例拷过去。

**自检**：新开一个空工作区，界面显示的是空状态还是示例？agent 要新增内容时，需不需要写工作区外的文件？

---

## 2. agent 不需要知道插件的布局和依赖链

**错误形态**：工具描述写“Requires node, ffmpeg and Playwright”；报错写具体文件路径；
系统提示写“片子在工作区的 motion/ 里”。结果 agent 去 `node -v`、`ffmpeg -version`、
`pwd`、`ls` 检查环境——在受限 shell 里这些会失败，于是它申请更高权限，用户看到一连串授权弹窗。

**规则**

- 工具/命令的返回值只给**内容**（时长、场景 id、槽列表），不给路径。
- 报错只说**下一步动作**（“这个工作区还没有片子，先建一条”），不点名文件。
- 依赖（运行时、浏览器、编码器）由插件自己的进程启动；不要写进描述让 agent 去“准备环境”。
- **不要用“不要做 X”的指令补漏**：如果 agent 必须去翻目录才知道怎么做，是接口漏了信息，
  不是它不听话。

**自检**：把插件的源码目录改名，agent 完成任务需要的信息是否仍然完整？

---

## 3. 内容以代码产出时，给 skill + 命令，不给工具面

**错误形态**：建片、写场景、改字、调参、渲染、导出各一个工具，共 11 个。每个都是窄接口，
每加一种内容就缺一块（“`motion_scene` 不支持素材”），而且把编程 agent 当表单填。

**规则**

- 只要产物是**用户可以用代码表达的东西**（场景、图表、版式），就让 agent 读 skill、自己写、
  自己跑。
- skill 讲清：目录布局、数据格式、模块契约、可用原语、确定性规则、命令、常见错误。
- 命令是唯一执行入口（`init` / `validate` / `render` / `export`）。校验失败就是命令退出非零。
- 命令要能被 agent 在**工作区内**直接调用：把自带 `bin/` 挂到宿主 PATH；子进程的临时目录
  （浏览器 profile、编码器中间文件）指向产物目录内，避免写工作区外。
- 只有“必须由工具保证的副作用”（原子写、并发保护、权限收口）才值得做工具。

**自检**：删掉全部工具后，agent 还能完成任务吗？如果不能，缺的是 skill 的内容，还是真的缺工具？

---

## 4. 面板是会话的一栏，不是并行的第二个世界

**错误形态**：面板自己收批注、自己存、自己回，按钮写着“发送给 Claude”却只置了一个布尔值；
面板不知道自己在哪个会话，因此既不能替会话说话，也不知道该显示谁的工作区。

**规则**

- 面板必须拿到**会话身份**，并据此解析该会话的工作区；路由按会话挂载
  （`/plugins/<id>/p/<session>/…`），面板里所有相对地址自然落在那个工作区。
- 人写的东西（批注、意见）走**人的消息**进对话（宿主已有排队 / 插入），不另立一套线程；
  面板只保留锚点与状态（时刻、区域、元素、处理没有）。
- agent 的话只说在对话里，面板不显示回复气泡。
- 面板不能是“要去打开的应用”：没有主区域面板顶掉对话，没有侧边栏入口逼人去找。
- **面板不自动打开**：右侧栏是用户的画布，不是插件抢来的位置。人从引导页打开它。
- 打开之后面板要**跟上产物**：空状态轮询到产物出现就重载，数据变化自动同步。

**自检**：把面板关掉，人的意见还能到 agent 那里吗？把面板打开，对话还在旁边吗？

---

## 5. 验证环境也是产品边界

**错误形态（同一项目里踩的）**：手动验证实例每次启动都删掉自己的 `DSH_HOME` → 会话全丢；
一个 shell 里继承了 `DSH_HOME=~/.dsh`，脚本照用 → 插件被装进用户主 profile，还和主 GUI 抢写；
从**受限沙盒里的 shell** 启动实例 → 它自己的 workspace-write 探测被嵌套沙盒挡住 →
判定“后端不可用” → agent 每条命令都要求授权，被误读成“这台机器沙盒坏了”。

**规则**：见 [10-install-and-verify.md](10-install-and-verify.md)「本地开发实例」——
独立进程 + **持久私有 home**（建一次、复用、不删）+ 随机端口；永不指向 `~/.dsh`；
凭据可以**拷一次**；**不要从沙盒化的 shell 启动实例**（先确认 `sandbox-exec -p '(version 1)(allow default)' true` 能跑通）。

---

## 一页速查

| 问题 | 错误答案 | 正确答案 |
|---|---|---|
| 用户产物放哪 | 插件安装目录 | 用户工作区，空则空状态 |
| 给 agent 的返回值 | 路径 + 环境要求 | 内容 + 下一步动作 |
| 怎么让 agent 产出内容 | 每个动作一个工具 | skill + 命令，自己写自己跑 |
| 人的意见怎么到 agent | 面板自建线程 | 作为人的消息进对话 |
| 面板不知道会话 | 让用户自己找 | 会话身份进路由 |
| 开发实例 home | 每次新建 / 用 `~/.dsh` | 持久私有 home，永不共享 |
